# Rust coverage accounting contract

The accepted committed baseline is `fbe76a5f15101ad415f355ef06f1deeb1f97d568`, tree `8db02719b5bd06d888729ca337f9bf8887991515`. The Actor started at isolated snapshot `d3c62cb034707d8cdbb30ba3ab51a392e92a6cce` with that same input tree. New tooling in this worktree is an uncommitted Actor-local change, not part of the accepted baseline. All measurements bind to actual input bytes as well as this provenance.

The current mandatory crates, in output order, are arc-core, arc-detector, arc-storage, arc-ipc, arc-daemon, arc-cli and arc-traffic. The accepted historical baseline contains the first six only. Each current crate must reach 80% production-source line coverage. This is a new engineering target, not an observed baseline or SRS threshold. Integer counts decide acceptance: `covered * 100 >= total * 80` using BigInt. Printed decimal rounding never decides acceptance; a high workspace average cannot compensate for one failing crate.

## Scope and denominator

Inventory every Rust file beneath the seven current `src` roots. Resolve external module declarations from production crate roots and integration-test roots, including explicit path attributes. A file reached by any production module is production even if integration tests also compile it using a path attribute. A file reached only from test modules is test-only. Unknown/unclassified files fail closed; filenames alone never decide exclusions.

Within a production file, tokenize comments, strings, raw strings and character literals before balancing Rust delimiters. Omit only whole items/statements/fields whose cfg expression is provably false with `test` disabled. The implementation handles the repository's `cfg(test)` and `cfg(all(test, ...))` forms and leaves unknown platform or feature predicates in production scope. `any(test, target_os=...)` remains production. Shared-line items are rejected as ambiguous, rather than dropping production lines. The source-inventory report lists the exact omitted line ranges and reason. This is a bounded lexical classifier for this repository, not a general Rust compiler parser; unsupported module layouts must fail and be implemented before acceptance.

Disable the tool's default filename filters because a path-included production module can have `tests/../src` in its recorded filename. Filter only exact non-workspace dependency roots from locked Cargo metadata, the Rust sysroot and compiler-source hash; record those roots in `non-workspace-roots.json`. No production filename is filtered.

An LLVM LCOV DA entry defines an instrumentable line. Canonicalize source aliases through realpath, then merge by workspace-relative path and line. Repeated compilations or module instances contribute one denominator entry; that line is covered when any instance has positive hits. Retain every mapped zero-hit production line. Remove test-only mapped lines and integration-test sources from both numerator and denominator. Never add assertion/helper lines to dilute the denominator. Do not exclude difficult production functions, modules, errors or platform paths. No coverage-only production cfg is enabled.

Before merging, validate every individual LCOV record, including test-only records. Standalone LCOV requires exactly one safe nonnegative integer `LF`/`LH` matching its unique DA entries and positive-hit entries. Reject duplicate DA lines, duplicate/missing summaries, invalid/unsafe values and summaries outside a source record. Validate before canonical union so a later compilation cannot hide an invalid earlier record.

The actual LLVM 22.1.2 exporter has distinct aggregations: [CoverageExporterLcov.cpp](https://github.com/llvm/llvm-project/blob/llvmorg-22.1.2/llvm/tools/llvm-cov/CoverageExporterLcov.cpp) emits DA from file-wide line data, but [CoverageReport.cpp](https://github.com/llvm/llvm-project/blob/llvmorg-22.1.2/llvm/tools/llvm-cov/CoverageReport.cpp) constructs LF/LH by summing function-group summaries. Those summaries can differ from unique file lines. The first real report reproduced this in 74 records. Preserve both raw outputs unchanged; never overwrite summaries to make validation pass.

For real measurements require a second fresh native JSON export (schema 3.1.0) from the same profile set. Require identical exact source-file sets, each original LF/LH equal the JSON function-group summary, and every DA line and count equal the complete line map reconstructed from JSON segments. Reconstruct using the pinned [LineCoverageStats and LineCoverageIterator](https://github.com/llvm/llvm-project/blob/llvmorg-22.1.2/llvm/lib/ProfileData/Coverage/CoverageMapping.cpp): account for wrapped segments, skipped regions, non-gap entries and maximum counts. Invalid/unsorted segments, missing/extra files or lines and changed counts fail. The denominator remains the canonical DA line union, never the function-summary count. Both native report hashes are retained and independently recomputed by evidence checks. Controlled standalone malformed-summary fixtures remain strict and unchanged; new corroboration fixtures reject missing zero-hit DA lines and mismatching native data.

Every production file must appear in the report. A present declarations-only file can have no DA entries, but every crate must have a positive denominator. Missing production files, unknown mapped paths outside the recognized integration-test trees, invalid or incomplete LCOV, out-of-range lines, unsafe/noninteger counts and missing/zero-denominator crates fail. Inactive whole-file platform modules will require an explicit reviewed inventory if introduced; they cannot silently disappear.

## Execution and freshness

The root command is exactly `bun run test:coverage`, backed by `bun scripts/coverage/run.ts`. It never installs tools and never invokes CLI/harness acceptance tests recursively. Provision separately with `mise run coverage:provision`: Rust 1.95.0, matching llvm-tools-preview, Bun 1.4.4, `cargo +1.95.0 install cargo-llvm-cov --version 0.6.21 --locked`, and `cargo +1.95.0 fetch --locked`. No JavaScript dependencies or lockfile are needed. The upstream pinned [release documentation](https://github.com/taiki-e/cargo-llvm-cov/blob/v0.6.21/README.md) describes LLVM tooling and report commands. Compatibility is established by a completed real instrumentation/report run and its numbered command receipts, not by configuration alone. Earlier denied provisioning receipts remain historical. Attempt 5 rechecked the operator's changed environment: matching LLVM tools, pinned cargo-llvm-cov and locked online/offline Cargo fetch succeeded. `mise install` still returned nonzero because its macOS cache path was denied; exact diagnostics are retained under `tooling/attempt-5/`. Installed Bun and Rust versions are checked directly before measurement.

Use `rustup run 1.95.0` for gate tool checks so a missing toolchain component cannot trigger implicit rustup synchronization. Check exact Bun, Rust and cargo-llvm-cov versions and LLVM's version against rustc. Reject unreviewed Rust/LLVM wrapper or flag overrides. Run one workspace/all-targets instrumented test pass with locked offline dependencies, no cfg(coverage), a new run target and `%p-%m` profile filenames. Existing CLI/daemon integration tests retain their subprocess ownership and coordination. Additional real binary probes (`arcctl --help` and a daemon startup rejection before admission) identify concrete child PIDs and require nonempty matching profiles. Compare the entire fresh raw-profile inventory against the pinned tool's actual llvm-profdata merge input list; each child's profile must be in that list.

Reports are immutable per UUID run under `baseline/runs/`. They include raw LCOV and JSON exports, seven current crate summaries, per-file mapped/omitted/uncovered line numbers, raw-profile hashes, child PID proof, exact commands, versions, platform and exit receipts. The latest pointer records every outcome, including failure. A fresh filename, both report timestamps and equal before/after input hashes prevent reuse. Fingerprints include all crate files (sources, tests, manifests, migrations), Cargo.lock, Rust/Bun configs, root package.json, the machine-readable accounting contract, any root .cargo config/build.rs and coverage implementation/tests. Changes during the run invalidate it. A failed current test or prerequisite exits nonzero before report evaluation; an old passing report cannot rescue it.

## Verification and boundaries

Controlled fixtures are synthetic LCOV/process inputs, never product measurements. `gate.test.ts` executes a fixture subprocess and checks the exact failure diagnostic for failed tests, absent/mismatched tools, absent/stale/malformed reports, source drift, missing files/crates and per-crate threshold failure despite an above-target workspace average. Accounting fixtures check canonical repeated-instance union, zero-hit retention, test-only omission and the exact 80% boundary. `coverage-cli.test.ts` executes the actual root command. `harness.test.ts` executes the unchanged harness with no skip flags. `preservation.test.ts` compares protected bytes against accepted HEAD and checks existing Rust tokens/assertions. `evidence.test.ts` recomputes the latest report from source-bound raw data. Cargo fmt/clippy/workspace tests remain separate native commands.

Measurement, when available, covers only the executed host's active cfg. The current host is aarch64-apple-darwin; each measurement records the actual Rust host and tool versions. `arc-core/src/lib.rs` has inactive non-macOS runtime, Windows LOCALAPPDATA and XDG branches; `arc-daemon/src/platform.rs` has Linux credentials and a fallback. They remain visible unmeasured platform obligations, not exclusions selected to pass 80%. Native Windows is not a supported gate host because current CLI/daemon use Unix sockets. Linux requires its own measured run. Stable-toolchain doc-test coverage is not collected by cargo-llvm-cov; workspace unit, integration and executable child paths are included.
