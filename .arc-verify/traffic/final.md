## Decisions and delivered scope

The selected design keeps child execution in `arcctl`, uses the existing classifier and daemon, and adds `arc-traffic` as the admission-policy boundary. The single SQLite worker serializes a durable FIFO queue, per-class windows, shared CPU and memory reservation estimates, permit transitions and lifecycle outcomes. A queued invocation gets an inline stderr notice and can be inspected with existing job status. This keeps the normal interaction to one direct invocation; the alternatives discussed were a second in-memory scheduling authority, a confirmation step and a separate mandatory queue console. Those alternatives add synchronization or user steps and were not selected. No new sales or distribution activity was authorized.

Direct local `cargo build`, `cargo test`, `cargo clippy` and `cargo fmt` are in scope. Build, test and lint each have a window of one; their reservations are respectively 2 cores/2 GiB, 1 core/1 GiB and 1 core/1 GiB, against a shared 2-core/4-GiB budget. These are admission estimates, not operating-system resource limits. Remote and UNKNOWN commands bypass reservations. A healthy queued invocation waits across bounded polling exchanges; an actual daemon outage retains bounded fail-open behavior. The CLI preserves native execution, streams and process supervision. Verified nested ancestry can reuse a lineage permit; the inherited context alone cannot. The implementation adds migration `0003_traffic.sql` while preserving the prior migration files and uses an additive capability-negotiated Traffic protocol with legacy protocol-1 fallback. See [managed execution](../../docs/managed-exec.md), [architecture advice](architecture.md) and [independent QA](qa.md) for the exact boundary and recovery limitations.
