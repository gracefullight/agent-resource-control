# Endpoint source notes

Each configuration read pass is bounded to regular, non-symlink files, 16 lookups and 8 KiB; the existing context entry, value, aggregate-size and five-second age checks remain in force. The operating system's local-interface inventory is sampled without a network lookup. Facts are transient and contain no DNS result.

Discovery runs in a one-shot worker with the same freshness deadline, so a stalled filesystem read cannot delay classification or return usable late facts. A timed-out worker may remain blocked until that read returns or the CLI process exits; it does not repeat reads or refresh facts.

- [Docker CLI context selection](https://github.com/docker/cli/blob/master/cli/command/cli.go) selects an explicit context, then an explicit host, then `DOCKER_HOST`, `DOCKER_CONTEXT`, the stored current context and finally `default`. Its default context uses the configured host or the default Unix socket. Named context metadata is addressed by the SHA-256 hash of its name and contains the Docker endpoint. Flags selecting both a context and a host conflict.
- A Unix-domain endpoint alone does not establish local compute: [OpenSSH can forward a local Unix socket](https://man.openbsd.org/ssh.1). On macOS, discovery inspects process and file-descriptor tables without connecting to the socket. A socket owned by the current user or root with one listener from the operator-specified local-engine list provides local placement; an SSH listener, unreadable table, missing listener or multiple candidates remains unknown. An independently selected remote Buildx node may still establish a remote result even if its Docker context uses a Unix transport. Platforms without this listener inventory remain unknown for Unix endpoints.
- [Buildx store](https://github.com/docker/buildx/blob/master/store/store.go) stores the selected instance by effective Docker endpoint, including a global selection and per-endpoint default. [Its configuration directory](https://github.com/docker/buildx/blob/master/util/confutil/config.go) honors `BUILDX_CONFIG`; otherwise it is below the Docker configuration directory. [Node-group records](https://github.com/docker/buildx/blob/master/store/nodegroup.go) include the driver and node endpoints. Capture accepts one non-dynamic node with a supported driver; multiple nodes, unresolvable names and unsupported drivers remain unknown. Docker SSH transports remain unknown because their separate OpenSSH configuration is not attested.
- [OpenSSH configuration](https://github.com/openssh/openssh-portable/blob/master/ssh_config.5) uses the first applicable value and can redirect through proxies. The default route reads the account home and system configuration in order; `ssh -F` substitutes one explicit file for both. A mismatched `HOME`, proxying, includes, `Match`, unsupported directives and unresolved DNS names remain unknown. The post-Git hook binds public Git-over-SSH hosts from the same restricted default configuration when an effective Git URL is supplied by the Git lane; unresolved hosts remain unknown.
- [Kubernetes client configuration](https://github.com/kubernetes/client-go/blob/master/tools/clientcmd/loader.go) merges a kubeconfig list using first-file precedence for named objects. An explicit `--kubeconfig` selects one file, `--context` selects the context, and `--namespace` or `-n` overrides its namespace. Cluster and server overrides remain unresolved. Capture binds the selected context, cluster and effective namespace to the API endpoint using distinct `KUBERNETES_CONTEXT` selectors. It does not launch `kubectl`, contact the cluster or emit a pod-placement fact. An API endpoint does not prove where a pod runs, so Kubernetes execution remains UNKNOWN/OBSERVE without external placement evidence.
- The [python-gitlab CLI reference](https://python-gitlab.readthedocs.io/en/v5.5.0/cli-objects.html) documents `GITLAB_URL` as the server URL override. Capture requires the explicit public value and no conflicting host selector. The offline stub does not establish whether a particular vendor binary supports the SRS's literal `pipeline run` command.

## Input budgets

An argv beyond the detector's byte or token limits must not trigger endpoint discovery. A fresh context with no environment or facts lets the shared execution route preserve the detector's `INPUT_LIMIT` or `TOKEN_LIMIT` diagnostic; a normal discovery failure still returns no context. The Git capture interface must also skip discovery for these inputs.
